# 八段 Prompt Recipe（候选 v0.1.0）

这些 Recipe 是 Skill 的候选运行框架，不替代 GEOFlow 数据库中的生产 Prompt。学习和复盘只能形成新候选版本，不能自行晋升。

## 1. 选题与页面职责规划

输入：产品、受众、采购意图、现有页面、关键词证据、目标渠道。先检查同一核心意图是否已有主页面；能更新时不新建近义页。每天提出 3–6 项有独立价值的内容或证据改进任务，证据不足时阻断，不凑数量。

## 2. 资料检索和证据提取

只从获准来源索引和文件提取。逐条保留来源 ID、主体、谓词、值、原文范围、适用范围、证据状态、公开权限、冲突和有效期。同行、第三方和 AI 只作结构学习；未找到就写未找到。

## 3. 内容母版生成

面向工业采购，以克制、清楚、可核查的语言生成官网文章、产品页候选、厂家页候选或公司介绍候选。必须写适用与不适用条件、询价输入、来源 ID 和待确认项。不得创造企业事实或参数。

## 4. 资质与参数复核

按 `references/evidence-policy.md` 逐条检查资质完整性、有效期和官方反查；参数必须来自恒佳同型号证据并保留单位、范围和工况。任一关键字段不满足即加入 blocker。

## 5. SEO/GEO、FAQ、内链与 Schema 组装

不新增事实地组装标题、H1、Slug、关键词、摘要、描述、FAQ、内链和 Schema。FAQ 直接回答采购问题并保留限定条件。Schema 只复述页面可见事实。

## 6. 渠道改写与字段映射

同一母版可调整结构、长度和开头，但主体、事实、参数、联系方式、来源和限定条件必须一致。WordPress、爱采购、1688、搜狐号、百家号都只输出候选字段；账号绑定和最终动作留给 GEOFlow。

## 7. 发布前检查

检查来源、资质、同型号参数、广告法高风险词、重复意图、账号主体串用、图片权利、FAQ 与 Schema 一致性，以及敏感凭据。强事实缺证、图片权利不明、账号不匹配或发现秘密均为 blocker。

## 8. 回读与复盘

Skill 本身不回读远端，只能复核 GEOFlow 提供的回执。严格区分生成、审核、发布、抓取、收录、排名、AI 提及和询盘；根据可复核数据提出 Prompt 候选改进，不自动替换生产版本。

## 统一输出提示

每次生成必须要求模型只输出 `hengjia-content-package/v1` JSON，并附原样的 Recipe 版本、输入 SHA-256、模型标识、生成时间和流水线版本。模型不能把 `blockers` 隐藏为普通备注。
